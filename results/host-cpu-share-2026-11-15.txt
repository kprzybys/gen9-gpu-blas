Conclusion: for LLM prefill the binary's CPU code does not limit speed; compiler options (-O2/-O3, -march) change
nothing measurable. Host-side loops exist only on fallback paths (CPU dequantization when GPU dequantization is
unavailable, F32 K/V attention of NeMo, F16 gather of PaddleOCR-VL); measure those workloads before optimizing them.
Found along the way: the library's top-level CMakeLists.txt failed when ~/src/llama.cpp existed (it still added the
removed ggml-backend/ directory), and the flag summary warned "no optimization flag" in C++-only projects; both fixed.
