# Fused attention kernel, stage 2 of docs/attention-gpu.md: bench/attn.cl + bench/attn.c (bench/attn.sh)
# Desktop HD 530 (i5-6500; Gen9 GT2, 24 EU, max 1050 MHz), NEO 24.35.30872.36, nice 19, 2026-11-13; background
# service ~30 % of one CPU core. GPU clock 1000 MHz in every sampled run (the first runs of variant A printed -1:
# a bug in the clock sampling, fixed afterwards; same kernels re-measured at 1000 MHz give the same times).
# One layer, non-causal, n_q 512, n_k 4096. Rate = 4 * n_q * n_k * H * d_head / time of the attention kernel
# (the K-transpose pre-pass k_kt, 0.28 ms Qwen / 0.58 ms Llama, is also given "incl. kt").
# Error = max |O - O_ref| / max |O_ref| against FP64 on the CPU for 33 query tokens (every 16th + last), all heads.
# Q float [H][n_q][D], K/V half [n_k][H_kv][D], O float [n_q][H][D] (llama.cpp layouts); random Q ~ N(0, 5^2),
# K, V ~ N(0, 1) (scores std 5, range about -20..20). All kernels SIMD8 (intel_reqd_sub_group_size(8)).
# Spill = CL_KERNEL_SPILL_MEM_SIZE_INTEL, private = CL_KERNEL_PRIVATE_MEM_SIZE (bytes per thread / per lane).
# Ceilings at 1.0 GHz: FP32 mad 384 GFLOPS (410 measured at ~1.07 GHz), FP16 ~770, SLM 177 GB/s.
# Stop criterion: >= 265 GFLOPS on the Qwen shape (2.5 x CPU 106) with error <= 2e-3.

## Design common to all variants
One SIMD8 subgroup = RQ query rows of one KV head (query heads of the same KV head, token-major). No SLM.
S = Q K^T with lane = key: K pre-transposed to [H_kv][n_k/8][D][8] half so a 128 B block read gives packed halfs
that fold into a mixed-mode mad (no conversion instruction); q[r][d] FP32 broadcast from lane-split registers
(scalar register region, no instruction). P V with lane = 8 dims of O; V row read as 64-half blocks; p broadcast.
Online softmax in FP32, native_exp2 with scale*log2(e) folded into Q, O rescaled only when the row max grows.
Q and O FP32 in registers: 16 GRF per row each at d_head 128 -> RQ <= 2 (Qwen), RQ <= 4 (Llama) without spill.

## Diagnostics (variant A code, ISA from ocloc -device whl and timing)
- Loop instruction mix, Qwen RQ 2 NK 2, per 16 keys: 1024 mad (all FP32 with folded hf sources), 64 SIMD8 64-bit
  address adds, 64 block reads, ~20 softmax ops; no conversions. Llama RQ 4 NK 2: 1024 mad, 32 address adds.
- n_k 512 (K/V of a layer fit L3) instead of 4096: same rate (Qwen 194.7, Llama 224.0) -> not LLC/RAM bound.
- ADV=0 (K/V pointers do not advance: same instruction stream, every read hits the same lines; wrong results):
  Qwen 268.6 GFLOPS (n_k 512: 248.2), Llama 260.8 (246.3). This is the ceiling of the compiled instruction stream:
  68-70 % of 384, i.e. about 265 even with perfect memory. The rest of the loss on real data is memory-side
  (Qwen -28 %, Llama -13 %) but not bandwidth: Llama RQ 4 (0.5 B/mad) is no faster than RQ 2 (1 B/mad).
- The mad stream has GRF bank conflicts (src1/src2 same parity, e.g. "mad r118 r118 r7.8:hf r95.0": 272 vs 410
  Gop/s measured for conflicting mads, performance-model.md) on about half the mads; IGC gives no control over it.
- Mixed-mode mad rate (new microbenchmark k_mix in bench/attn_micro.cl, clbench, global 131072, local 64, n 400):
    MIX=0 (float operand)            323.1 / 324.5 GFLOPS  GPU ~1000 MHz
    MIX=1 (packed half operand)      323.0 / 323.6 GFLOPS  GPU ~990-1000 MHz
  -> FP32 mad with a packed FP16 source runs at the full FP32 rate (fills the gap in attention-gpu.md section 7).

Reading: slower than A and above the 2e-3 error bound -> rejected. The FP16 mads take a broadcast scalar operand
(loses the double rate, performance-model.md section 2) and each partial sum is a chain of 8 dependent mads.
Q in half does not save registers either (IGC keeps one GRF per SIMD8 half component), so RQ cannot grow.

## Variant C (non-fused S, softmax, P V): skipped. The fused FP32 kernel is accurate to 2e-6 and its compiled
## instruction stream alone tops out at ~265 GFLOPS; a non-fused version adds 100 MB of S/P traffic per layer
## (Qwen, n_k 4096) and short-K (128) GEMMs, so it would not reach 265 either without hand-written assembly.

## Verdict
Best (non-spilling): Qwen 215 GFLOPS (2.0x CPU 106), error 2.1e-6; Llama 234 GFLOPS (2.2x CPU 107), error 1.6e-6.
Stop criterion (265 GFLOPS, 2.5x) NOT met; prediction for variant A (200-300) met at its lower end.
Limits: (1) the IGC-compiled mad stream reaches only ~68 % of the FP32 peak even with every read hitting
(bank conflicts on ~half the mads + address/softmax overhead) = ~265 GFLOPS at 1.0 GHz, no margin;
(2) registers: FP32 Q + O take 32 GRF per row at d_head 128, so a subgroup holds only 2 rows and every K/V element
serves 2 rows; (3) a further 13-28 % is lost on real K/V streams (not bandwidth, not latency of loads).
FP16 arithmetic (variant B) fails the accuracy bound.
