# Register budget of an accurate HGEMM loop (FP16 chunk sums carried into FP32) with an R x 32 tile, Gen9 128 GRF
# 2026-11-13, for the accurate-HGEMM work (gemm_gen.py / hgemm_kc). Scripts: experiments/solver/gemm_*.py
# (gemm_extract.py, gemm_epi.py on kp-laptop, read-only use of asm/gemm_gen.py and asm/attn_gen.live_in;
# gemm_solve.py: CP-SAT on the 32-thread desktop, OR-Tools 9.15.6755, 144 configurations, 0.4 s). No GPU run; nothing measured.
#
# CORRECTION (same day, after implementing liveness in asm/gemm_gen.py): the E = 9 / 7 scenarios came from
# attn_gen.live_in, which assumes full SIMD8 masks. A sound analysis for the SIMD16 GEMM epilogues (only (W) full writes
# kill, multi-register operands counted, e.g. r86.0<8;8,1>:d also reads r87) frees: h 68, hd 57, s 74 registers vs
# 71 / 62 / 79 under the old text rule, which was itself unsound (it freed registers the epilogue reads). Even with a
# full-dispatch-mask assumption hd gains only 1 register (63). => the accurate 16x32 tile does NOT become feasible this
# way; the E = 9 / 7 rows below are optimistic and should not be used.
#
# Overhead taken from the existing kernels (gemm_extract.py / gemm_epi.py):
#   kind  acc GRF  ptr  cnt/lim  epilogue regs mentioned (free_regs blocks them)  live into the epilogue (of them headers)
#   h     32       4    1        17                                               9 (2)
#   hd    48       4    1        10                                               9 (1)
#   s     32       4    1         9                                               8 (1)
# -> E = 17 (today's free_regs), 9 (live-in), 7 (live-in minus send headers zeroed after the loop).
#
# Model: hf accumulators R x 2 GRF, FP32 accumulators R x 2 pairs of 2 GRF, per buffer A (R*kl*2 B) + B0 + B1 (kl GRF
# each), all blocks at even registers (gemm_gen layout, zero bank conflicts), headers 3 per buffer or 3 shared;
# fixed r0, r1, r127, 2 pointers x 2 GRF, counter/limit 1, E. Accumulators placed freely (best case).
# CP-SAT status equals the count bound in every case (no fragmentation effect).
#
# Summary (need / 128)
# 16x32: E=17: nothing fits (minimum 130).
#        E=9:  kl4 x1 128 (no spare); kl2 x2 shared headers 128; kl2 x1 122.
#        E=7:  kl4 x1 126; kl2 x2 shared 126.
#        kl4 x2 (quarters double-buffered, as hd today) and every kl8: impossible (>= 138).
#        kl2 means 2-GRF blocks = 64 B sends instead of 128 B.
# 8x32:  fits everywhere (kl8 x2 at E=17: 119); but 6.4 FMA per loaded element vs 8 for 16x16 and 10.7 for 16x32.
#
