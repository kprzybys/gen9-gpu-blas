# Kernel catalog

Every GPU kernel in this repository: where it lives, what it does, who calls it and the measured result. State
2026-11-15 (branch `ggml-backend`). All numbers are from the UHD 620 (WHL GT2, i5-8265U) unless stated; sources are
the result files and docs named in each row. How to write a new kernel: [kernel-guide.md](kernel-guide.md); why the
numbers are what they are: [performance-model.md](performance-model.md).

Two delivery paths: OpenCL C compiled offline with `ocloc 24.35 -device whl` (binaries embedded by
`lib/gen_kernels.py`), and hand-scheduled Gen9 assembly generated by `asm/gemm_gen.py` from an OpenCL template
(`asm/*.cl` -> `bench/*.bin`). Both run either through Intel NEO or through **kcl** (`lib/kcl.c`, our own submission
path on i915 without NEO, [no-neo.md](no-neo.md)).

## 1. GEMM cores (gen9blas)

| Kernel | Binary / source | What it does | Result |
|---|---|---|---|
| `hgemm_v` | `bench/gen_h.bin` (asm, template `asm/gen_h.cl`) | FP16 GEMM, FP16 accumulation, 16x32 tile per thread, packed A2 / BQ inputs | 699 GFLOPS whole call n = 4096, 777 kernel only (`results/compare-onednn-2026-11-11.txt`, `results/hgemm-compare-2026-11-11.txt`) |
| `hgemm_kc_v` | `bench/gen_hd.bin` (asm) | FP16 inputs, FP32 sums of 32 products (K % 32 == 0), FP16 C; packed A3 / B16 | 618 GFLOPS n = 4096, error 1.5e-5 vs 1.4e-4 for `hgemm_v`; used by the ggml backend, `emb/` |
| `sgemm_v` | `bench/gen_s.bin` (asm, template `asm/gen_s.cl`) | FP32 GEMM, 16x16 tile, packed `pkf_a` / `pkf_b` | 344 GFLOPS n = 4096 (85 % of the 402.8 GFLOPS measured FMA peak); used by `ina/`, `silero/`, `emb/` (FP32 mode) |
| `dgemm_v` + `pkd_*` | `bench/dgemm.cl` (generated), `bench/dgemm_core.cl` | FP64 GEMM | 57 GFLOPS (slower than OpenBLAS on the CPU; this GPU has weak FP64) |
| `hgemm_16x32*`, `hgemm_16x16kc*`, `sgemm_16x16p*` | `bench/hgemm.cl`, `bench/sgemm.cl`, `asm/hgemm*.cl` | OpenCL C ancestors / templates of the asm kernels, kept for comparison and as asm templates | see [history.md](history.md) |
| `skinny_q4k`, `skinny_q4k_t` | `bench/skinny_q4k.cl` | GEMM with few rows (M = 1..16, LLM token generation) straight on Q4_K weights | 4096x4096 FP16: 1.5 ms at M = 1 vs 10.4 ms through packing; memory-bound limit 1.3-1.5 ms ([skinny-gemm.md](skinny-gemm.md)) |

**Packing and epilogues** (`bench/hgemm.cl`, `bench/sgemm.cl`, `bench/packing.cl`): `pk_a2`, `pk_a3`, `pk_bq`, `pk_b16`
(macro-generated, + `_t` transposed), fast variants `pk_a2_q`, `pk_a3_q`, `pk_bq_w2`, `pk_b16_w2`, `pk_a3_f32` /
`pk_a3_f32v` (FP32 rows -> FP16 A3 through SLM with 16 B stores), `pkf_a` / `pkf_b` (+ `_t`);
`gen9blas_dequant_b16` (Q4_K / Q8_0 weights dequantized on the GPU straight into the packed layout, bit-identical to the
CPU path); epilogues `gen9blas_epilog_b`, `_f`, `_fb`, `_hf`, `_hf8`, `gen9blas_epilog_hf8x` (bias, GELU and residual
fused into the GEMM write-back), `_tri` / `_trif` (triangular); `gen9blas_swiglu_pack_a3` (SwiGLU fused into the
packing of the next GEMM's input).

**Level 3 beyond GEMM**: `trsm_L_*`, `trsm_Y_*`, `trsm_store_*`, `trsm_inv0..3_*` (blocked TRSM with inverted
diagonal blocks), `gen9blas_syr2k_merge_*`, `gen9blas_expand_*` (`_h`, `_f`, `_d` variants). Full BLAS level-3 API:
[api.md](api.md).

## 2. BLAS levels 1-2 (`bench/level12.cl`, `bench/l12.cl`)

axpy, copy, dot, nrm2, iamax, rot, rotm, scal, swap; gemv (`gemv_n`, `gemv_nw`, `gemv_t1`, `gemv_t1b`, `gemv_t2`), ger,
symv (`symv1`, `symv2`), syr2, trsv (blocked: `trsv_block`, `trsv_upd_n`, `trsv_upd_t`). Kernels are generated per
type by a macro. Memory-bound; GPU pays off only for large vectors and when the CPU is busy
(`results/level12-2026-11-12.txt`). A single-launch "sync-free" TRSV was 3-8x slower than the blocked one (pitfalls.md).

## 3. ggml backend operations (`ggml-backend/ggml-gen9.cpp`, kernels in `bench/hgemm.cl`)

Used by llama.cpp, whisper.cpp and NeMo-Speech.cpp ([ggml-backend-design.md](ggml-backend-design.md)).

| ggml op | Kernel | Notes |
|---|---|---|
| MUL_MAT | `hgemm_kc_v` / `skinny_q4k` + packing / dequant | weights packed once and cached (also mmapped GGUF, `GEN9_RO_WEIGHTS`); bias / GELU fused (`epilog_hf8x`) |
| FLASH_ATTN_EXT | asm attention `bench/attn_*_tokc.bin` (one binary per head size / model: llama, qwen, qwen3, qwen7b, whisper, nemo); OpenCL reference `bench/attn.cl` (`k_kt`, `k_attn`) | 296-301 GFLOPS = 2.8x the CPU ([attention-gpu.md](attention-gpu.md)); F32 K/V converted on the GPU (`gen9blas_cvt_f16_heads`) |
| RMS_NORM, NORM | `gen9blas_rms_norm`, `gen9blas_layer_norm`, `gen9blas_layer_norm_pack` (norm fused into the next GEMM's packing) | |
| ADD, MUL | `gen9blas_binop_rows` | |
| UNARY GELU / GELU_ERF, GLU | `gen9blas_gelu`, `gen9blas_gelu_erf`, `gen9blas_swiglu_pack_a3` | |
| ROPE | `gen9blas_rope` | off for NeMo's older ggml (changed its results) |
| IM2COL, RELU | `gen9blas_im2col`, `gen9blas_relu` | test-backend-ops 1010/1011; in Nemotron no measurable time difference (results/diar-...-2026-11-14.txt section 20) |

Results: llama.cpp Q4_K_M / Q8_0 prompt processing 2.3x the CPU, 3.2x less energy, 2.6-3.3x OpenVINO; whisper
large-v3-turbo Polish RTF 0.41; Nemotron diarization 1 h in 66.5 s (CPU 278 s).

## 4. Speech pipelines (kcl, no NEO, own `.so` each)

Applications built on them: `bench/diar/hybrid.py` (diarization), `bench/diar/voices.py` (speaker identification),
`bench/diar/transcribe.py` (recording -> SRT with speakers and names, one machine).

## Counting

346 `__kernel` entry points in 33 `.cl` files (many repeat: the `asm/*.cl` templates copy their OpenCL ancestors), plus 6 asm GEMM binaries and 10 asm attention binaries; the ones that
matter in production are the three GEMM cores (`hgemm_v`, `hgemm_kc_v`, `sgemm_v`), the asm attention, the packing /
epilogue / element-wise set of the ggml backend and the four speech pipelines (mel, ina, silero, emb).
